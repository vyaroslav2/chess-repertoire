## Decisions
- Opening name: Inter 14px, letter spacing -0.0062em (Inter's recommendation for 14px), `#979490` (6.05 : 1).
- Coordinates: Arial 13px, weight 400, `#817e7a` (4.52 : 1), with Arimo as a self-hosted stand-in where Arial is missing.
- Move numbers and moves: Roboto, one font for both, as Lichess does. Numbers 14px, centred, no dot, in a shaded column (`#33312e`) running flush top to bottom. Moves 16.59px.
- Move list panel: 220px.
- Evals: in the move's cell, right-aligned, JetBrains Mono 0.8em, weight 300, `#949494`, two decimals (-9.99 to +9.99). Lichess's cell padding (0.5em, 0.3em). The panel grows to 318.4px when they arrive.
- New colours meet the 4.5 : 1 contrast guideline; the move numbers on the shading (2.9 : 1) are still open.
- Judge type at its final size, not zoomed: zoomed comparisons misled the letter-spacing choice.
- HE's eval profile is Stockfish 19 at 2M nodes (Threads 1, MultiPV 1), not depth 24. Why: about 2 s a search, and within ±300 cp, where the curve is steep, it matches 200M closely. Beyond that the curve is nearly flat, so bigger deep evals barely change a prior.
- One profile for all of HE: the curve, each contender's prior and the engine checks all use 2M nodes. Deeper evals (e.g. the project's 200M) are not read off a 2M curve: they may run about 8% larger (growth 1.08 ± 0.07), which shifts a prior by about 0.7% at ±100 cp, always the same way. A move searched deeper is searched again at 2M for its prior.
- Mates stay out of the curve, as before. The slight lean towards Black with deeper search (about 2–3 cp) is small enough to ignore.
- With a node limit the search can stop part-way through a depth. The result is the last exact score, from the deepest completed depth, and a root search reports that depth's move, even where bestmove (from the unfinished depth) differs. Why: it is what the node tests measured, and it never fails a long run.
- Two engine profiles. The generator keeps its deeper search (200M nodes since `341d2b5`) to pick and store Black's move; 2M nodes is HE's only. Why: the stored eval picks the move and judges it sound, so depth pays off; a prior only needs the curve's measure. Using 2M everywhere would be cheaper but weaker: the best move differed from 200M in 2 of 20 repertoire positions and 6 of 28 HE positions. When HE runs inside the project, each contender is searched again at 2M nodes for its prior.
- The Colab split: the friend runs `jobs-a`, the user `jobs-b`. Both use `colab/he_colab.py` unchanged.
- Job format: JSONL, one job per line (`id`, `positionKey`, the group's first FEN, `uci`). A group's FENs differ only in the clocks, so the first stands for all.
- Results format: JSONL, one line written as each search ends (`id`, `uci`, `cp` or `mate`, `depth`, `nodes`, the last exact `info` line, `bestmove`), plus a `session` line at each start with the engine, its SHA-256, bench and settings. The score is kept as Stockfish gives it (Black's view); the import flips it to `cpWhite`, in one place. Why: Colab drops sessions, so each result must be saved at once and a run must resume; a flip by hand on two machines would go wrong unnoticed.
- Identical results on any machine: the same Stockfish 19 release (SHA-256 checked), `bench` = 2,497,913 checked every session, Threads 1, Hash 64, MultiPV 1, `ucinewgame` and Clear Hash before each search, `go nodes 2000000 searchmoves <uci>`, never a time limit. Speed varies with the machine; results don't.
- Only the move's eval is searched for the curve and k, not the position's baseline.

- Evals only on moves that appear on cards. A White move that ends a route has no reply and no card, so no eval.
- What an eval means ([[DB|DB.11]]): one figure is Stockfish's estimate of the position after the move, in White's view. Two in a row give what the move cost. After Stockfish's own top move they differ only by search noise.
- Generator engine: one thread, one search at a time, no parallel searches. Why: simpler code, and results repeat exactly. About 3.3 min a search, so about 6.6 min a card.
- A search stopped by the node limit takes the score and move of the deepest completed depth, not `bestmove`, as in HE.
- A Black move that mates stores `mate = -1`, one that stalemates `cp = 0`; neither is searched.
- Hash stays 1024 MB for now. If swapping comes back, 256 MB: a little weaker per search, but always in RAM.
