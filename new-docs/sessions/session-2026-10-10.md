## Decisions
- Only the board is centred. The move list sits beside it, 188px wide and as tall as the board.
- The opening name is as wide as the board and lines up with its left edge.
- The board's sizes are pixel-exact for one screen only: 1920 × 1080 at 125%, browser zoom 100%. A temporary fix. A layout that is exact at any size (whole screen pixels per square, our own grid, recomputed on resize and zoom) is deferred.
- The board is 691.2px, the size Lichess shows on this screen. The edge is 1 screen px and the lines between squares 2, as on Lichess.
- The status line above the board is temporary and will be redone; layout figures ignore it.
- All HE evals and graphs use White's view (`cpWhite`). On the curve, Black's score falls as the eval rises.
- The pilot has no bug, but one sampled move per game means groups with 200+ games form only at move 2, near 0 cp. More games won't change that. The scatter check (HE 2a) needs another plot, not more data. k is not affected: it is fitted on all groups with 2+ games.
- The fit sample changes from January 2024 (1–2 January, a holiday) to February 2024, 50,000 games, same seed and filters. A second, independent 50,000 comes from March 2024. Compare February with March, then join them into 100,000 and compare with 50,000 (HE footnote 1). Start with 50,000: cheaper if something goes wrong.
- Empty the `games` table before loading February; `load` adds to it and there is no run column. Keep the January files on disk.
- The curve and k need only the eval of the move played (`searchmoves`), not the position's baseline search.
- The evaluations are split between the user and a friend on Google Colab: the friend takes the first 20,000 groups, the user the rest. Both use the same Stockfish 19 build and identical settings.
- A shallow search of about 2M nodes (about 2 s) is the candidate eval profile, instead of depth 24. It is checked in stages to catch mistakes cheaply: 2M against 50M (passed), then 2M against 200M.
- One eval profile for all of HE: the curve, each contender's prior and the engine checks. If the project's own evals are deeper (200M nodes), the gap must be measured, or contenders searched again at 2M nodes for their prior.
