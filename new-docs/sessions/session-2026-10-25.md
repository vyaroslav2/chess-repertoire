## Done
- Bug fixed: the opening name disappeared after the last move of `d4 d5 Nf3 Nf6 g3 c5`. The position after `c5` had no opening status (missing): the run had stopped before naming it. 8 of 423 nodes were like this. Now the generator names every node as soon as it stores it, so a stopped run leaves none missing ([[DB|DB.06]]). `npm run fill-opening-names` retries missing names, parents first; it named the 8 in `dev.db`. The trainer still never guesses a missing name.

## Decisions
- No fallback to the previous name in the trainer for a missing status: after a transposition it would show the wrong opening. A name Explorer doesn't have is already copied from the parent when stored (DB.06 rule 2), so the data is right and the trainer only reads it.
- No rule for Anki cards whose line isn't in the database. Every card comes from the database; a hand-made one would at worst show no name until its last move.
