# Step 0: Stop-Request Handling (Setup)

S0.01 At the very start of the run, the script registers a listener for [[sigint|`SIGINT`]] — the OS signal Ctrl+C sends. 

S0.02 You press Ctrl+C at any point during the run. The OS delivers `SIGINT` to the running process immediately.

S0.03 The listener fires right away — it sets an internal flag (`stopRequested = true`) and prints straight to the console. This one message never reaches the run log ([[TGL]]), even once logging is running: it always uses the raw, un-intercepted console output.
    
> `"Stop requested; generation will stop after the current position."` 

This message appears the instant you press Ctrl+C — not later. 
    
S0.04 **The main loop doesn't stop instantly.** It's mid-processing whatever position it's currently on. Only at the very top of the _next_ iteration does it check the flag ([[S3|S3.01]]). If set, it throws a specific internal signal — `UserRequestedStopError` — rather than an ordinary crash.

S0.05 That error unwinds up to the outermost `try/catch`, which distinguishes _why_ the run ended: if the thrown error is specifically that stop-request type, the log gets a closing line tagged `[STOPPED]`; any other kind of error gets `[FAILED]`; a clean, uninterrupted finish gets `[FINISHED]`.

S0.06 Regardless of which of those three happened, the same cleanup always runs: disconnect from the database, then release the lockfile, which checks ownership before removing anything ([[LF|LF.10]]). 

S0.07 A second Ctrl+C simply sets the same flag again and reprints S0.03's message; there is no force-quit path, so holding Ctrl+C does nothing a single press did not already do.

S0.08 The flag is read in one place only, at [[S3|S3.01]]. A Ctrl+C pressed anywhere else — during the lockfile retries ([[LF|LF.06]]), the wipe ([[S2|S2.04]]), or a rate-limit wait of `lichessRateLimitRetryDelayMs` ([[generation-config]], 120 000 ms) — is acknowledged at once by S0.03's message but acts no sooner than the next loop iteration. Two minutes of apparent silence is the worst case.[^1]



[^1]: #note Accepted, not a bug. The alternative is checking the flag inside every wait and retry, which spreads stop-handling across [[LF]], [[S2]] and [[EX]] instead of keeping it in one place.
