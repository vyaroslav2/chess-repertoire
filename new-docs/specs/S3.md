# Step 3: Main Queue Loop

S3.01 Check if the user sent `SIGINT`[^7] ([[S0]]), if so stop.   

S3.02 Is the queue empty?  
* yes `-->` Done -- print the summary. Set `[FINISHED]` tag when probability totals balance, required responses are verified, metadata is settled, and every unfinished-looking branch has an explicit ending reason. 
* no `-->` continue.

S3.03 Take the next item off the queue.[^2] Is the node already in `visitedList`?
* yes `-->` skip it and continue to the next queue item.
* ==no `-->` add this node to the in-run `visitedList` and process.[^8]==




S3.07 Hand off to [[HM]]. 



[^2]: #note LIFO (last-in first-out) is decided for this generator architecture -- LIFO  leads to depth-first approach, where we expand the first line to full depth before continuing to the next one. FIFO on the other hand, leads to breadth-first search. That means we go through all move 1 opponent plies and our responses, before continuing to move 2.  

[^7]: OS signal `Ctrl+C` sends which terminates console.

[^8]: Do we do this at the beginning of the loop (after dequeuing) or at the end?
