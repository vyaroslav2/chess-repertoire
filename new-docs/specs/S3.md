# Step 3: Main Queue Loop

S3.01 Check whether the user has asked to stop — [[sigint|`SIGINT`]] ([[S0]]). If the flag is set, throw `UserRequestedStopError` ([[S0|S0.04]]). This is the only place the flag is read ([[S0|S0.08]]).

S3.02 Is the queue empty?
* yes `-->` go to S3.16.
* no `-->` continue.

S3.03 Take the next node off the queue.[^1] Is it already in `visitedNodes`?
* yes `-->` skip it and continue to the next queue item.
* no `-->` add it to the in-run `visitedNodes` and process. Marking happens here, at dequeue, not after processing.[^2]

S3.07 Hand off to [[HM]].

S3.08 Control comes back here when the position has been dealt with: [[HM]] filters White's moves, [[EW]] picks Black's reply, and [[RE.excalidraw|RE]] either ends the route or pushes the next position onto this queue ([[RE.excalidraw|RE.09]]). Then return to S3.01.

S3.09 Push order. The queue is LIFO, so the last position pushed is the first one taken. The queue holds positions after Black's reply. To read a log that runs from White's most popular move down to its least, they are pushed in order of the White move that led to them, least popular first.

S3.16 Run a depth recheck sweep ([[DRS]]). 
* routes reopened `-->` they are on the queue. Return to S3.01.
* none reopened `-->` the run is over. Go to S3.10.
## End of run

S3.10 Print the summary ([[TGL]]). It includes `rareDroppedMovesTotal`: all nodes with `stopReason = Too rare`.

S3.11 Probability balances: ending total + `rareDroppedTotal` + `unaccountedDroppedTotal` + `tinyDroppedTotal` come to 100%, within `probabilityTolerance`. Each cascade has already kept the sum of all four unchanged ([[TR.excalidraw|TR.41]]).


S3.12 Every Black response has `deepVerified` set to true ([[DB|DB.14]]).

S3.13 Every node carries opening metadata, either `PRESENT` or `VALID_ABSENCE` ([[DB|DB.06]]).

S3.14 Every route that ends carries a `stopReason` ([[DB|DB.20]]).

S3.15 All four pass `-->` return normally. Any one fails `-->` throw a hard error. [[S0|S0.05]] writes the closing tag.

[^1]: #note LIFO (last-in first-out) is decided for this generator architecture. LIFO leads to a depth-first approach, where we expand the first line to full depth before moving to the next. FIFO leads to breadth-first: we go through every move-1 opponent ply and our replies before starting move 2.

[^2]: At dequeue is the safe order: a position can be pushed again while it is being processed, and marking at the end would let that copy through. Marking at dequeue also means a position queued twice before either copy is reached is only ever processed once.
