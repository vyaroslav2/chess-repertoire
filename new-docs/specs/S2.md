# Step 2: User, Repertoire, Wipe, Seed Queue

S2.01 Print the startup message[^2], start the timer, ==zero out the run counters[^3].==

S2.02 Find in the DB the user `Yaroslav`, or create that user if missing.[^4]

S2.03 Find in the DB ==Yaroslav's repertoire titled "Black Universal Repertoire"==; if missing, create it with colour Black.

S2.04 Wipe the previously generated tree for this repertoire ==— both [[node|nodes]] and moves ([[DB|DB.02]]).==[^1] ==What survives is every cache: Explorer data, engine evaluations, opening metadata and Wikibooks text ([[DB|DB.30]]).==

S2.05 Check whether the root position exists in the ==Explorer cache (`PositionCache`, [[EX|EX.01]]) — reuse it or create it.==[^5]

S2.06 Set the [[root-probability|root's probability]] -- 100%. ==Both `routeProb` and `cumProb`; at the start of a run every node has one equal to the other ([[TR.excalidraw|TR]]).==

S2.07 Put the root into the queue. Continue to [[S3]].

S2.08 ==The `Position` table — the `positionKey` to owning-node index that [[TR.excalidraw|TR.03]] matches on — is not mentioned here, and [[DB|DB.02]] only wipes nodes and moves. It has to be wiped as well.==[^6]







[^1]: #note Wipe and rebuild is the intended truth. No reconciliation. 

[^2]: See [[TGL]]

[^3]: ==#question Which ones? The cascade counters (revisits, refires, duplicates, tinyDropped) are reset per cascade at [[TR.excalidraw|TR.23]], not per run. The run-level ones — `rareDroppedTotal`, `tinyDroppedTotal` — belong here. Worth naming them outright.==

[^4]: ==#question The user name, the repertoire title and the colour are fixed in the text but appear nowhere in [[generation-config]]. Either they are settings (`userName`, `repertoireTitle`, `repertoireColour`) and belong there, or they are deliberately hardcoded and this note should say so.==

[^5]: ==Worth being exact about which store. There are two, and they behave oppositely across a wipe: `PositionCache` holds Explorer answers per [[cache-profile|cache profile]] and survives ([[DB|DB.31]]); `Position` is the transposition index and cannot (S2.08). "Position cache" reads like either one.==

[^6]: ==#bug If `Position` survives a wipe, every `positionKey` from the previous run is still claimed, so [[TR.excalidraw|TR.03]] answers yes for positions whose owning node no longer exists. [[TR.excalidraw|TR.08]] would then point `transposesTo` at a deleted node and the first run after would be the only correct one. Nothing in these notes currently says it is wiped.==
