Where that bites: fresh ChessDB
results built in B2.20 have no
mate field at all, so getCp()
returns NaN for them.

Every comparison against NaN is
false. Therefore, while using
those fresh ChessDB results:

• a candidate that matches a
  ChessDB line is REJECTED

• a candidate that does not
  match is sent to deeper search

Cached ChessDB rows do not have
this problem because their mate
field is stored as null. ^Mav3Oa00

M.01 · The shared maths and
the fixed numbers used across
A1-A4 and B1-B5. ^bv6yS1n2

M.02 · Smoothed win rate
(the maths file)

score = White wins + half the draws

result = (score + 50 x 0.52)
         divided by (games + 50) ^JqTPlMn4

M.03 · Used twice, both for White:
the master win rate and the
amateur win rate, when deciding
whether a White move is worth
covering. ^KXgKLVAY

M.05 · Tolerance table
(the engine file)

moves 1-4:   80, local 95
moves 5-8:   50, local 60
move 9 on:   35, local 40

In centipawns - hundredths of a pawn. ^35THXcQM

M.07 · Reading a score
(the engine file)

If mate is exactly null:
• use the centipawn value
• if centipawn is missing,
  use zero

Otherwise treat it as mate:
• positive mate:
  30000 minus mate value
• zero or negative mate:
  -30000 minus mate value

Important:
if mate is missing rather
than null, this calculation
produces NaN. ^An0pTpgu

M.09 · The other fixed numbers

master games count 5 times an
elite game (B1.5)

a move needs 15 weighted games
to survive (B1.7)

the imaginary prior is 50 games:
52% for White
48% for Black

candidate tolerance:
moves 1-4: 80 cp
moves 5-8: 50 cp
move 9 on: 35 cp

local-engine tolerance:
moves 1-4: 95 cp
moves 5-8: 60 cp
move 9 on: 40 cp

shallow local engine:
15 moves, depth 18

forced-mate deep search:
1 move, depth 24

tactical sweeper:
flags a difference over 150 cp ^NPGOL4FY

Black's version of the win rate is
not this function. B1.6 writes the
same formula out by hand with 48%
instead of 52%. Two copies of one
idea, in two places. ^Uljc6pv7

The maths file holds a second
tolerance table (80 / 50 / 35, no
local column). Nothing imports it.
The one that actually runs is the
engine file's. Dead code that reads
as if it were live. ^xn4f6qbp

Why smoothing: a move played once
and won once is not a 100% move.
Adding 50 imaginary games at
roughly even pulls thin evidence
back towards even, and leaves
well-played moves almost untouched. ^hZgQ6JuP

Why 30000: it is far beyond any
real centipawn score, so a forced
mate always outranks any ordinary
move, and mate in 2 outranks
mate in 5 because fewer moves
subtracts less. ^MM61NA7G
