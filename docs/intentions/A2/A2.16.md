### A2.16 — Position within both depth limits -> A3: which White moves do we cover?

**What the code does**  
This box is reached when the current position has passed both checks in A2:

- it has not been stopped by the ordinary depth-limit check in [[A2.10]];
    
- its trap/threat continuation depth has not reached the limit checked in [[A2.17]].
    

Nothing is changed at this box.

It is the hand-off from A2 into A3.

The same current position now continues into the White-move selection part of the generator.

Immediately after these depth checks, the code fetches the master, elite and amateur database data for the position and then begins building the set of White moves that A3 will consider.

**Why this matters**  
A2 answers only whether the current position is allowed to continue.

A2.16 marks the point where that decision has been made: according to the current code, neither depth check has stopped the branch.

The algorithm can now spend work on deciding which White moves from this position should be included in the repertoire.

So this box separates two different questions:

A2: "Are we allowed to expand this position?"

A3: "Which White moves from this position should we cover?"

A2.16 itself does not fetch moves, choose moves or alter the position. It only marks the transition between those parts of the algorithm.

Because of the existing depth-limit issue, "within both depth limits" describes the current code's flow rather than the intended final relationship between the ordinary depth limit and trap/threat continuation. See [[A2.10]] for the related `#bug`.

**Why it may have been designed this way**  
Likely: this box exists mainly to make the boundary between the A2 and A3 diagrams explicit.

A2 contains the rules that decide whether expansion may continue.

A3 contains the rules that decide which White moves are worth covering once expansion has been allowed.

There is no separate hand-off operation in the code because these are sections of one continuous generator function.
