### A2.01 — Position in hand, from A1

**What the code does**  
A2 begins with the same queued position that A1 has just prepared.[^2]

Nothing is fetched, calculated or changed at this box. It is the receiving side of the hand-off from A1.21.

The position already carries:

- the board position;
    
- the database node ID;
    
- the current full-move number;
    
- the trap/threat continuation depth;
    
- the cumulative probability;
    
- the move history.
    

The algorithm now starts deciding whether this position is allowed to expand.

The next thing it uses is the position's cumulative probability.

**Why this matters**  
This box makes clear what A2 is working on.

A2 does not create a new position or copy selected information into a different object. It continues working with the same queued item that A1 took from the front of the queue.

That matters because the decisions made in A2 depend on values that were attached to the position earlier, especially its cumulative probability, current move number and trap/threat continuation depth.

So A2's expansion limits are properties of the particular branch currently being processed, not global properties of the whole queue.

**Why it may have been designed this way**  
Likely: this box exists mainly to make the boundary between diagrams explicit.

A1.21 says that A1 is handing the current position over to A2.

A2.01 shows the same position arriving on the other side before A2 begins applying its expansion rules.

There is no corresponding hand-off operation in the code because A1 and A2 are diagram sections of one continuous generator function.
