### A2.18 — This branch has reached the trap/threat continuation limit — stop. Add one to the branches-aborted count and print an `[ABORTED]` message → back to A1's loop top

**What the code does**  
This box is reached when [[A2.17]] finds that the current position's `trapDepth` is `8` or more.

The generator:

- prints an `[ABORTED]` message;
    
- says that the trap refutation limit of `8` has been reached;
    
- says that zero White moves were processed for this position;
    
- adds `1` to the branches-aborted counter;
    
- stops processing this position and returns to the top of A1's queue loop.
    

No White moves are fetched or considered for this position.

The position itself has already been counted as processed earlier in [[A1.19]].

**Why this matters**  
This is where the current code enforces the maximum length of an active trap/threat continuation.

Once this box is reached, the generator does not expand the position any further. Anything already created earlier in the line remains in the repertoire; only further expansion from this position stops.

The next queued position can then be processed normally.

The intended production continuation limit is still an open decision recorded in [[A2.17]].

The relationship between this continuation limit and the ordinary depth limit is covered by the `#bug` in [[A2.10]] rather than repeated here.

**Why it may have been designed this way**  
Known: the continuation needs a finite stopping point so that a trap or threat line cannot keep extending indefinitely.

The current value `8` came from treating the allowance as if it were measured in plies rather than full moves. See [[A2.17]] for the open production-limit decision.
