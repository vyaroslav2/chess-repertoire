### A2.02 — Read the cumulative probability this position is carrying

**What the code does**  
The generator uses the cumulative probability already stored on the current queued position.

It does not calculate or change that probability here.

For the root position, the cumulative probability starts at `1.0`, meaning 100%.

For positions reached later in the repertoire, the probability has already been calculated earlier and carried with the queued position.

The value represents the probability accumulated along the path that led to this position.

A2 now uses that value to choose a depth budget.

**Why this matters**  
The depth decision is based on how likely this particular branch is to be reached.

A position on a more probable path can receive a larger depth budget.

A position on a less probable path receives a smaller one.

So A2 is not looking only at how deep the position already is. It first looks at how important the branch is according to its cumulative probability.

The value belongs to the current queued position. Different positions in the queue can therefore carry different cumulative probabilities and receive different depth budgets.

**Why it may have been designed this way**  
Known: this allows the generator to spend more depth on common branches and less depth on rare branches.

Instead of applying one fixed depth budget equally to every branch, the intended design gives more potential work to positions that are more likely to occur.
