### A2.12 — Too deep — stop this branch. Add one to the branches-aborted count and print an `[ABORTED]` message naming the depth limit that was hit → back to A1's loop top

**What the code does**  
This box is reached when [[A2.10]] finds that the current position's full-move number is greater than the effective depth limit.

The generator:

- prints an `[ABORTED]` message;
    
- includes the effective depth limit in that message;
    
- includes the current position's cumulative probability;
    
- says that zero White moves were processed for this position;
    
- adds `1` to the branches-aborted counter;
    
- stops processing this position and returns to the top of A1's queue loop.
    

No White moves are fetched or considered for this position.

The position itself has already been counted as processed earlier in [[A1.19]].

**Why this matters**  
This is where the current code actually enforces the ordinary depth limit.

Once this box is reached, the current position is finished. The generator does not delete anything already created earlier in the branch; it simply does not expand this position any further.

The next queued position can then be taken and processed normally.

This abort happens before the trap/threat continuation logic is reached. See [[A2.10]] for the related `#bug`.

**Why it may have been designed this way**  
Known: this box exists to stop ordinary branches once they have gone beyond the depth allowance selected for them, while recording that the branch was deliberately stopped rather than silently disappearing.

The `[ABORTED]` message and counter make these deliberate depth stops visible when reviewing a generator run.

The current placement before the trap/threat continuation check does not match the confirmed intention for trap/threat lines.
