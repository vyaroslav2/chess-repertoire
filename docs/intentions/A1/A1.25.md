### A1.25 — Start the counters and the timer

**What the code does**
Just before the work begins, the generator prints a line saying it is starting, notes the current time, and sets a group of counters to zero.

There are eleven counters: positions processed, branches abandoned, White moves found, White moves skipped, mainlines, master threats, amateur traps, Black replies evaluated, missing White moves, missing Black replies, and evaluations with no engine score.

They live in memory for the length of the run. They are read twice: at every node, to print the running checkpoint in [[A1.24]], and once at the end, for the summary in [[A1.15]].

**Why this matters**
These eleven numbers are the only measure you have of what a run did. Nothing about them is stored, so once the run ends and the log ages out, the figures are gone.

They are also the only way to notice something going wrong quietly. A run that produces a tree of the expected size but with a large count of missing Black replies has failed at something, and no single log line would tell you — only the total does.

Because they start at zero every run and count only that run, two runs cannot be compared except by reading two logs side by side. That is what the per-run log files in [[R.02]] were partly for.[^1]

Several of them count things that overlap: a move counted as a mainline is also counted among White moves found; a skipped move is counted under its own tag as well. So they cannot simply be added together.[^2]

**Why it may have been designed this way**
Known: the counters cover both what was built and what went wrong, which suggests they were added to answer "did that run work" rather than to measure size.

Likely: they were added as needed while the generator was being written, rather than designed as a set — which would explain why some overlap and why the naming is uneven.

**Also affects:** [[A1.15]] (the summary that reads them), [[A1.24]] (the checkpoint that reads them), [[A3.08]] and [[A4.22]] (among the places that raise them)

Notes:

[^1]: #note Today figures exist only in the log, and only until that log ages out. Writing the eleven totals into the database at the end of each run would let you compare runs over time — how many positions, how many missing replies, how long it took. Small addition; decide once the per-run logs exist.

[^2]: #note The counters overlap deliberately: a mainline is also a White move found, and a skipped move is counted under its tag as well as in the skipped total. They are separate tallies of the same events, not parts of one whole, so they cannot be added together.
