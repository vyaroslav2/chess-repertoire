### A4.32 — Work out the new cumulative probability: current × this move's popularity

**What the code does**  
The generator calculates the cumulative probability of reaching the position after this White move.

Conceptually, it multiplies:

`probability of reaching the current position × popularity of this White move`

In the code:

`const incomingPathProb = node.cumulativeProb * (whiteMove.probability || 1.0);`

For example, suppose the current position has a cumulative probability of `20%`.

If this White move is played in `10%` of Amateur games from that position:

`20% × 10% = 2%`

The new cumulative probability is therefore `2%`.

Another example:

- current cumulative probability: `8%`;
    
- this White move's popularity: `25%`;
    
- new cumulative probability: `2%`.
    

The calculated value is called `incomingPathProb` in the code.

It is then used later when the generator records the White move, creates or merges repertoire nodes, and eventually puts the continuation back into the queue.

The next box is [[A4.08]].

**Why this matters**  
This lets the generator keep track of how likely the whole route through the repertoire is, rather than looking only at the popularity of the latest White move.

Each new White move makes the path probability smaller according to how often that move is played.

For example:

`100% × 40% × 20% × 10% = 0.8%`

So even if the latest move itself is played 10% of the time, the complete line may already be quite rare because of the moves that came before it.

This cumulative value is what A2 later uses when deciding which probability-based depth tier a queued position belongs to.

**Why it may have been designed this way**  
Known: cumulative probability is intended to measure how likely the user is to encounter the complete line.

Multiplying the probabilities along the route allows common lines to remain relatively important while increasingly rare branches naturally fall into lower probability tiers.
