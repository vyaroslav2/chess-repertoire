### A4.11 — Print a `[TRANSPOSITION]` merging message. Record White's move as leading to that existing node, storing its popularity and the new cumulative probability

**What the code does**  
This box is reached when [[A4.08]] found an existing repertoire node for the position after White's move and [[A4.09]] confirmed that the node already has a saved training card.

The generator prints a `[TRANSPOSITION]` message saying that this position has already been fully expanded and that the tree is being merged.

It then creates a repertoire move from the current node to the already-existing node.

The saved move contains:

- White's SAN;
    
- `playerTurn: "OPPONENT"`;
    
- the White move's local popularity;
    
- the new cumulative probability for this particular route.
    

In the code, those last two values are stored separately as:

- `prob` = the popularity of this White move from the current position;
    
- `trueProbability` = the cumulative probability of reaching the existing position through this particular route.
    

The existing repertoire node itself is not recreated.

The algorithm then continues to [[A4.13]], where the existing node's stored cumulative probability is updated.

**Why this matters**  
This is the actual merge point for a transposition that has already been fully trained.

The new route is still recorded as a White move, so the repertoire retains the fact that this position can be reached through another move order.

But the generator does not create another copy of the destination node or another training card for it.

That matches the SRS goal of learning one response for one shared training position while still preserving the additional route that reaches it.

The distinction between `prob` and `trueProbability` is important:

- `prob` describes how often this particular White move is played from its parent position;
    
- `trueProbability` describes how likely this complete route is from the repertoire root.
    

**Why it may have been designed this way**  
Known: a transposition should not create a duplicate flashcard when the destination position is already trained.

Recording the new move into the existing node preserves the alternate route while reusing the already-selected Black reply and training card.

The exact rules for deciding when two positions are safe to merge belong to the transposition/position-identity design already discussed in [[A4.08]].
