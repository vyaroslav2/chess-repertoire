### A4.04 — Take the next included White move with its reason, flags, and popularity. Use the reason and flags to decide whether it will count as a mainline, trap, or threat. Print the move, its `[TRAP]` or `[THREAT]` prefix when applicable, its reason, and its popularity

**What the code does**  
A4 takes the next White move from the included list.

It reads the move's two flags:

- `isAmateurTrap`;
    
- `isMasterThreat`.
    

It then works out three local labels:

- `isTrap` = the Amateur Trap flag;
    
- `isThreat` = the Master Threat flag;
    
- `isMainline` = reason is `"Mainline"` **and** neither the trap nor threat flag is set.
    

So a move whose reason is `"Mainline"` does not count as a mainline here if it is also carrying one of those flags.

For the printed prefix:

- trap -> `[TRAP]`;
    
- otherwise threat -> `[THREAT]`;
    
- otherwise no prefix.
    

Trap therefore has priority in the printed label if both flags were ever true at the same time.

The generator then prints:

- the White move SAN;
    
- its reason;
    
- its probability as a percentage;
    
- the `[TRAP]` or `[THREAT]` prefix when applicable.
    

For example, conceptually:

`[TRAP] Evaluating White Move: Nf3 (Reason: Mainline, Prob: 6.2%)`

is possible in the current code because the reason and the flags are separate pieces of information.

After printing, the algorithm continues to [[A4.05]].

**Why this matters**  
This box turns the classification produced by A3 into the labels that later A4 code uses for counting and continuation behaviour.

The distinction between the move's `reason` and its flags is important.

A move may have reason `"Mainline"` but still be treated downstream as a trap or threat because A4 checks the flags separately.

The actual counters are not increased at this box. A4.04 only works out how this move should later be counted. The increments happen on the later exit paths after the move has been dealt with.

The probability printed here is the probability value carried from A3. For Master Threats, that may already include the deferred 1% floor discussed in [[A3.05]].

**Why it may have been designed this way**  
Likely: the code separates classification from counting because a White move can leave A4 through several different paths - transposition, cached Black reply, newly evaluated Black reply, or failure.

Working out the labels once at the start means each later successful path can use the same `isMainline`, `isTrap` and `isThreat` values when updating its counters.

The current interaction between `"Mainline"` reasons and trap/threat flags belongs to the deferred logic in [[A3.05]] rather than being redesigned here.
