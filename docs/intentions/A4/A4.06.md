### A4.06 — Extend the history with this move

**What the code does**  
The generator creates a new move-history array by taking the current position's existing history and adding the White move that has just been played.

In the code:

`const newHistory = [...node.history, whiteMove.san];`

It then also creates a space-separated text version:

`const newPgn = newHistory.join(" ");`

The original `node.history` array is not changed. A new array is created for this White-move branch.

For example, if the incoming history is:

`["d4", "d5", "c4"]`

and the current White move is:

`"e3"`

then:

`newHistory = ["d4", "d5", "c4", "e3"]`

and:

`newPgn = "d4 d5 c4 e3"`

The algorithm then continues to [[A4.07]].

**Why this matters**  
The generator needs to remember not only the board position but also the exact sequence of moves that led to it.

This extended history is used later for several purposes, including:

- identifying repertoire paths;
    
- creating or finding later repertoire nodes;
    
- printing meaningful error and progress messages;
    
- carrying the move sequence forward when Black's reply is added.
    

Creating a new array instead of modifying the old one also keeps sibling White branches separate.

If two White moves are being explored from the same parent position, each gets its own history rather than one branch accidentally modifying the history used by another.

**Why it may have been designed this way**  
Known: the generator needs both the chess position and the path that produced it.

The FEN tells the programme what the board looks like, while the move history tells it how this repertoire branch reached that board.

Keeping history as an array also makes it easy to append another move as the branch grows.
