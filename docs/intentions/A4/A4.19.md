### A4.19 — Did Diagram B find a move?

**What the code does**  
This box is reached after [[A4.16]] has asked Diagram B to choose Black's reply.

A4 checks whether Diagram B returned a selected move:

`if (!algoResult.selectedMoveSan)`

So:

- no selected move -> go to [[A4.21]];
    
- selected move exists -> go to [[A4.22]].
    

A4 does not decide here why Diagram B failed or succeeded.

It only checks whether B returned a move SAN that A4 can use.

**Why this matters**  
Diagram B can finish without producing a usable Black move.

A4 therefore needs a clear boundary between:

- "B found a reply, so continue building the repertoire";
    
- "B found no reply, so this White-move branch cannot continue".
    

This check prevents A4 from trying to play, store or create a training card for a Black move that does not exist.

If B did find a move, A4 continues with the normal successful-response path.

If not, [[A4.21]] records the failure and returns to the next included White move.

**Why it may have been designed this way**  
Likely: Diagram B contains several ways for Black-move selection to fail, but A4 does not need to know the internal reason at this point.

A4 only needs one simple contract from B:

"Did you return a selected Black move or not?"

That keeps the Black-move-selection logic inside B and the repertoire-building logic inside A4.
