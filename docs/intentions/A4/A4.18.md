### A4.18 — Loop back to A4.01 for the next included White move

**What the code does**  
After [[A4.15]] has updated the counters for the current White move, the code executes:

`continue`

This immediately ends processing for that White move and returns to the `for (const whiteMove of whiteCandidates)` loop.

If another included White move remains, A4 begins processing that move.

If there are no included White moves left, the loop ends and the flow eventually returns to [[A1.24]] through [[A4.03]].

No further work is done on the current transposition branch.

In particular, the generator does not:

- evaluate another Black move;
    
- create another training card;
    
- put the transposed continuation on the queue.
    

The existing destination position already has its saved training card, so this route stops at the merge point.

**Why this matters**  
This is what makes the transposition branch actually stop.

The alternate White route has already been recorded as leading to the existing position, but the continuation beyond that position is not generated again.

So conceptually:

- preserve the new route into the position;
    
- reuse the existing training position;
    
- do not duplicate its continuation;
    
- move on to the next White move.
    

That matches the transposition model recorded in [[A4.08]].

**Why it may have been designed this way**  
Known: once a later route reaches a position that has already been fully expanded, that route should merge into the existing repertoire rather than create a duplicate flashcard and duplicate continuation.

The `continue` statement is the code mechanism that ends work on this White move and resumes the surrounding White-move loop.
