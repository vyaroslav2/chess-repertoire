### A4.02 — Any moves left in the list?

**What the code does**  
A4 works through the included White moves one by one.

Conceptually, this box asks whether there is another White move from [[A3.08]] still waiting to be processed.

In the code, this is represented by:

`for (const whiteMove of whiteCandidates)`

There is no separate `if` statement that literally asks "are any moves left?". The `for` loop itself provides that behaviour.

If another move remains, the loop takes it and continues to [[A4.04]].

If no moves remain, the loop ends and execution continues after A4, reaching the per-position checkpoint in [[A1.24]] before A1 takes the next queued position.

**Why this matters**  
This is the control point for A4's one-by-one processing of White moves.

A3 may pass several included White moves into A4, but A4 does not process them all at once.

Instead, each move goes through its own A4 path:

- take one included White move;
    
- process it;
    
- either finish or skip that move;
    
- return for the next included White move.
    

Only after every included White move has been dealt with does A4 finish for the current position.

**Why it may have been designed this way**  
Likely: each included White move can lead to a different board position, transposition, Black reply, training card and queued continuation, so each one needs to be processed independently.

Representing the loop explicitly in the diagram makes that repeated behaviour easier to follow even though the source code expresses it with a normal `for` loop.
