### A4.17 — Print a [SKIPPED API] message naming the reply that was chosen. Play it on the board

**What the code does**  
This box is reached when [[A4.14]] finds an existing training-card record for the position after White's move.

The generator reads the Black repertoire move referenced by that card:

`existingStat.targetMoveId`

If that move exists, it prints:

`[SKIPPED API] Already generated in DB! Black responds with: ...`

So Diagram B is not called again. The generator reuses the Black reply that is already stored in the training card.

It then plays that saved Black move on the temporary board:

`tempChess.move(dbBlackMove.san);`

and reads the resulting FEN:

`const fenAfterBlack = tempChess.fen();`

The history has not yet been extended in this box. That happens as part of the queued item in [[A4.20]].

After playing the saved reply, the algorithm continues to [[A4.20]].

**Why this matters**  
This is the reuse path for a training position that already has a chosen Black response.

Instead of asking Diagram B to choose the move again, the generator treats the training card's `targetMoveId` as authoritative and follows that saved response.

That prevents the generator from recalculating a different Black reply for a position whose training answer has already been saved.

It also avoids the API and engine work that Diagram B would otherwise perform.

**Why it may have been designed this way**  
Likely: once a training card exists, its saved target move is meant to remain the repertoire answer unless the user deliberately changes it.

Reusing the saved move also makes re-runs cheaper and more stable because the generator does not repeatedly re-evaluate positions that already have a chosen response.
