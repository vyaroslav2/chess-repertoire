### A4.21 — No valid Black move — add one to the missing-Black-moves count and print an `[ALERT - ERROR]` message. Nothing more is done for this White move -> back to A4.01 for the next included White move

**What the code does**  
This box is reached when [[A4.19]] finds that Diagram B did not return a selected Black move.

The generator prints:

`[ALERT - ERROR] No valid Black move found after ... Stopping branch.`

The message includes the move history up to and including the current White move.

It then adds `1` to the running missing-Black-moves counter:

`totalMissingBlackMoves++`

After that, the code executes:

`continue`

This stops processing the current White move and returns to the A4 loop for the next included White move.[^3]

The generator does not:

- create a Black repertoire move;
    
- create or update a training card for this position;
    
- create the position after Black's reply;
    
- put a continuation from this White move onto the queue.
    

**Why this matters**  
This lets the generator continue even when Diagram B cannot produce a usable Black response for one particular White move.

The failure is recorded in the run statistics instead of crashing the whole repertoire-generation process.

The White move itself has already been recorded earlier in [[A4.12]], so the repertoire can contain the position after White's move even though no Black reply was successfully attached to it.

That leaves this branch incomplete rather than deleting the work already done before Diagram B failed.

**Why it may have been designed this way**  
Likely: failure to choose one Black reply should not stop the entire generation run.

Recording the failure and moving to the next White move allows the rest of the repertoire to continue building while still making the missing response visible in the logs and final summary.

[^3]: #bug If Diagram B returns no valid Black move after all of its normal selection and fallback logic has been exhausted, generation should stop with a hard error. The current code instead continues the run and leaves a partial repertoire branch in the database: the White move and resulting position are stored, but no Black response or training card is created.
