### A4.31 — Count this move under its tag — mainline, trap or threat

**What the code does**  
The generator updates the running counters for the White move that has just been fully processed.

It checks three flags:

- `isMainline`;
    
- `isTrap`;
    
- `isThreat`.
    

Then it increments the corresponding counters:

`if (isMainline) totalWhiteMainlines++;`

`if (isTrap) totalWhiteTraps++;`

`if (isThreat) totalWhiteThreats++;`

These values were worked out earlier in [[A4.04]] from the White move's reason and trap/threat flags.

A move counts as a mainline only when:

`whiteMove.reason === "Mainline" && !isTrap && !isThreat`

So a move whose inclusion reason is `"Mainline"` does **not** count as a mainline here if it also carries a trap or threat flag.

A trap and a threat are checked separately.

That means, if a move somehow has both flags set, the current code increments **both** counters.

After updating the counters, the algorithm continues to [[A4.28]].

**Why this matters**  
These counters are used for the generator's running and final summaries.

They describe how many included White moves were actually processed under each category.

The important distinction is that this counting is based on the move's final flags, not merely its inclusion reason.

For example, a White move might have passed the filter because it met the ordinary mainline popularity threshold while also carrying an Amateur Trap flag.

In that case:

- its reason can still be `"Mainline"`;
    
- but A4.31 counts it as a trap rather than as a mainline.
    

That matches the existing A3/A4 behaviour where trap and threat flags take priority over the `"Mainline"` reason for classification.

**Why it may have been designed this way**  
Likely: the counters are intended to describe the character of the repertoire branches rather than merely which filter rule happened to include each move.

So a move carrying a trap or threat flag is counted under that special category even if it was popular enough to qualify as a mainline anyway.
