### A4.05 — Play the move on a copy of the board. This gives us the position after White's move

**What the code does**  
The generator creates a new chess-board object from the current position:

`const tempChess = new Chess(node.fen);`

It then plays the current included White move on that board:

`tempChess.move(whiteMove.san);`

The original queued position is not changed. The move is applied only to this temporary board copy.

After the move has been played, the generator reads the resulting FEN:

`const fenAfterWhite = tempChess.fen();`

This FEN represents the chess position immediately after White's move.

The temporary board remains in use later in A4, so Black's chosen reply can subsequently be played on the same board.

The algorithm then continues to [[A4.06]].

**Why this matters**  
A4 needs the actual board position produced by each included White move.

That resulting position is used later to:

- identify the position in the cache;
    
- look for an existing repertoire node;
    
- detect transpositions;
    
- evaluate and play Black's reply.
    

Using a fresh board object for each White candidate also keeps the candidates independent. Processing one White move does not alter the starting board used for the next White move.

**Why it may have been designed this way**  
Likely: using a temporary copy is the simplest way to calculate the exact resulting chess position without changing the queued position that A4 is currently expanding.

That lets A4 repeatedly start from the same position and explore each selected White move separately.
