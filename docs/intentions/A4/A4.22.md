### A4.22 — Add one to the Black-moves-evaluated count. If Diagram B returned no selected engine score (null), also add one to the N/A-evaluations count. Print the chosen move with its score, volume, evaluation source, and evaluation

**What the code does**  
This box is reached when [[A4.19]] confirms that Diagram B returned a selected Black move.

The generator first adds `1` to the running Black-moves-evaluated counter.

It then checks whether the selected engine score returned by Diagram B is `null`.

If it is `null`, the generator also adds `1` to the N/A-evaluations counter.

So a Black move can still have been successfully selected even when no selected engine score is available.[^1]

The generator then prints information about the chosen Black move, including:

- the move SAN;
    
- its score;
    
- the amount of human-game data associated with it;
    
- which evaluation source was selected;
    
- the displayed evaluation.
    

The exact values come from the result returned by Diagram B. A4 does not recalculate them here.

After printing the result, the algorithm continues to [[A4.23]].

**Why this matters**  
This box records that Diagram B successfully produced a Black response.

The Black-moves-evaluated counter therefore measures successful Black-move selections that reached this stage, rather than every attempt to call Diagram B.

The separate N/A-evaluations counter records successful selections where the chosen move did not have a usable selected engine score.

That distinction is useful because:

- "no Black move was found" is handled earlier as a failure in [[A4.21]];
    
- "a Black move was found, but its selected engine score is unavailable" is allowed to continue here.
    

The current code allows the repertoire to continue even when the selected Black move has no engine evaluation. This occurs when Diagram B falls back to a human candidate without an engine score. See the `#bug` below.

**Why it may have been designed this way**  
Likely: the generator treats choosing a usable Black move as the primary requirement, while engine-score availability is secondary information.

Keeping a separate N/A counter makes missing evaluation data visible without forcing the whole branch to fail when Diagram B was still able to choose a response.

The detailed rules for how Diagram B chooses the move and evaluation source belong to Diagram B rather than A4.22.

Notes:

[^1]: #bug Diagram B can currently fall back to a human candidate that did not pass the normal human-move selection and engine-verification logic, leaving the chosen Black move with no engine evaluation. That should never happen. If the human-move selection logic fails to produce an engine-validated move, the fallback must be the top engine move. An unvalidated human move must never be allowed through. Every saved Black response must have an engine evaluation; if none can be obtained, generation should fail rather than save an unevaluated response. This matters because the move is written to the repertoire two boxes later at [[A4.25]] and then studied — so the fault reaches your actual book, it is not only a miscount.
