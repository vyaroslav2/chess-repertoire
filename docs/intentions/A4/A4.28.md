### A4.28 — Update the trap/threat continuation counter

**What the code does**  
The generator calculates the `trapDepth` value that will be carried into the next queued position.

The rule is:

- if the current branch is already inside a trap/threat continuation, add `1`;
    
- otherwise, if the current White move starts a trap or threat continuation, set the value to `1`;
    
- otherwise, set it to `0`.
    

In code, this is effectively:

`nextTrapDepth = trapDepth > 0 ? trapDepth + 1 : (isTrap || isThreat ? 1 : 0)`

So the counter does not measure individual plies. It advances once for each complete White-and-Black move cycle that continues through this part of A4.

Examples:

- ordinary branch, ordinary White move: `0 -> 0`;
    
- ordinary branch, White move starts a trap/threat: `0 -> 1`;
    
- already inside continuation: `1 -> 2`;
    
- already inside continuation again: `2 -> 3`.
    

Once the counter is above `0`, the current code keeps increasing it regardless of whether later White moves themselves carry a trap/threat flag.

The resulting value is passed to [[A4.27]], where the position after Black's reply is queued.

**Why this matters**  
This is how A4 carries trap/threat continuation state forward to the next position.

Later, [[A2.17]] reads this counter when deciding whether the special continuation has reached its depth limit.

So A4.28 creates the state that A2 later uses.

**Why it may have been designed this way**  
Likely: once a trap or threat line begins, the generator needs to remember that fact across later positions rather than relying only on the flags of each individual White move.

The exact rules for when a continuation should start, stop, or how long it should last are deferred.
