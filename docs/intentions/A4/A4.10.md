### A4.10 — If no node exists, create one carrying our new cumulative probability. If the newly created node is an Amateur Trap or Master Threat, save that flag and print a message. If an unexpanded node already exists, reuse it without changing its flags or its cumulative probability

**What the code does**  
This box can be reached in two situations:

- [[A4.08]] found no repertoire node for the position after White's move;
    
- [[A4.08]] found a node, but [[A4.09]] found that it does not yet have a saved training card.
    

If no node exists, the generator creates one.

It passes:

- the current repertoire ID;
    
- the FEN after White's move;
    
- the extended move history;
    
- `incomingPathProb`, the cumulative probability of this exact route.
    

The creation helper normalises the FEN before storing the node.

If the White move carries an Amateur Trap or Master Threat flag, the generator then saves that flag on the newly created node and prints a corresponding message.

If an unexpanded node already exists, none of that creation logic runs.

The generator simply keeps using the existing node.

In that case it does not update:

- the node's cumulative probability;
    
- its Amateur Trap flag;
    
- its Master Threat flag.
    

After either path, the algorithm continues to [[A4.12]], using `posAfterWhiteNode` as the destination node for the White move.

**Why this matters**  
This box makes sure A4 has a repertoire node representing the position after White's move before it records the White move itself.

For a genuinely new position, the node is created with the probability of the route that reached it.

For a position that already exists but has not yet been expanded into a training card, the existing node is reused rather than creating another one.

The trap/threat flags are saved only when the node is newly created. The deferred Amateur Trap and Master Threat design is covered in [[A3.05]] rather than decided here.

The current transposition lookup problem and the consequences for reaching the existing-node branch are already documented in [[A4.08]].

**Why it may have been designed this way**  
Likely: a newly discovered position needs a repertoire node before its incoming White move and eventual Black response can be attached to it.

Reusing an existing unexpanded node would avoid creating two repertoire nodes for the same position while still allowing the position to continue through the normal Black-response flow.
