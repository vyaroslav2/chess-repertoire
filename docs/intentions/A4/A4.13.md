### A4.13 — Raise that node's cumulative probability to the larger of its current value and ours

**What the code does**  
This box is reached after [[A4.11]] has connected the current White move to an already-existing transposition node.

The generator compares:

- the cumulative probability already stored on that existing node;
    
- the cumulative probability of reaching it through the new route.
    

It then keeps whichever value is larger.

In the code:

`Math.max(posAfterWhiteNode.cumulativeProb, incomingPathProb)`

For example:

- existing route probability: `4%`;
    
- new route probability: `2%`;
    
- stored cumulative probability remains `4%`.
    

If instead:

- existing route probability: `2%`;
    
- new route probability: `4%`;
    
- stored cumulative probability becomes `4%`.
    

So the current code does not add the probabilities of multiple routes together. It stores only the largest individual route probability.

The algorithm then continues to [[A4.15]].

**Why this matters**  
The cumulative probability stored on a transposed node influences how important that node appears later in the generator.

However, once a position can be reached through more than one route, the meaning of this field becomes important.

The current implementation treats the node's cumulative probability as:

"the probability of the most likely single route that reaches this position"

rather than:

"the total probability of reaching this position through all repertoire routes".

Those are different quantities.

For example, if the same position can be reached through:

- route A: `4%`;
    
- route B: `2%`;
    

the current stored value is `4%`, not `6%`.

**Why it may have been designed this way**  
Likely: using the larger value preserves the probability of the most likely individual route when the same position is reached through a rarer transposition.

It also avoids repeatedly adding the same route probability if the generator processes the same repertoire again.

However, it does not represent the combined probability of all distinct paths into a transposed position.

The intended probability model for transpositions is part of the position/transposition design discussed in [[A4.08]].
