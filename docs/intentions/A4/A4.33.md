### A4.33 — If the entry is new, try to fetch an opening description from Wikibooks. If one is found, save it

**What the code does**  
In [[A4.07]], the generator calls:

`getOrCreatePositionCache(fenAfterWhite, undefined, newHistory)`

The helper first normalises the FEN and checks whether that board already has a `PositionCache` entry.

If the cache entry is **new**, the helper starts with:

`wikiText = null`

Because A4 supplies the move history, it then calls:

`fetchWikibooksSnippet(history)`

using the complete move history up to and including the White move.

For example, if the current line is:

`1. d4 d5 2. c4`

the history supplied here is effectively:

`d4 d5 c4`

The Wikibooks helper is therefore asked for an opening description corresponding to that line.

If it returns text, that text is stored in the new position-cache entry as:

`wikiText`

If it returns nothing, the position-cache entry is still created, but `wikiText` remains `null`.

A4.33 does **not** determine whether the White move should be included, and the Wikibooks result does not affect generation of the repertoire branch.

After this work inside the cache helper, A4 continues to [[A4.32]] and then the position/repertoire-node logic that follows.

**Why this matters**  
This attaches human-readable opening information to the shared cached chess position.

The opening description is therefore metadata about the position, rather than part of the algorithm's decision about which repertoire moves to keep.

Because `PositionCache` is shared by normalised FEN, a description fetched once can later be reused whenever that same chess position is encountered.

A failure to obtain a Wikibooks description does not stop generation.

**Why it may have been designed this way**  
Likely: opening descriptions are useful for later display and explanation, but they are not important enough to make repertoire generation depend on an external informational source.

Fetching the description only when the cache entry is first created also avoids repeatedly requesting the same information for a position already in the cache.
