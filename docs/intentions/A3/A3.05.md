# A3.05 — Filter White opponent moves

  

## What the code does

  

The current code runs every distinct White move from [[A3.04]] through the existing filter.

  

Current code still calculates:

  

```text

Amateur popularity

Master Threat flags

Master Threat popularity floor

Amateur Trap flags

mainline popularity bar

```

  

and then applies the current first-match inclusion rules:

  

```text

Mainline

Master Threat

Amateur Trap

Drop

```

  

That description remains useful as a record of current implementation behaviour.

  

However, Master Threat and Amateur Trap are no longer part of the intended architecture.

  

## Intended behaviour

  

`Known:` White OPPONENT move coverage should use only Amateur human-move data.

  

Masters and Elite statistics must not affect whether a White move is included.

  

For every candidate White move, calculate:

  

```text

popularity

= this move's Amateur games

÷ total Amateur games at this position

```

  

If there are no Amateur games:

  

```text

→ no White moves can be selected from this source data

```

  

Required source-data failure is handled earlier by F and must not be confused with a genuine successful empty result.

  

## Popularity thresholds

  

`Known:` The current intended popularity thresholds are:

  

```text

moves 1–4

→ 5%

  

moves 5–8

→ 10%

  

move 9+

→ 15%

```

  

These values come from the central config and use the shared move bands in [[M]].

  

## Inclusion rule

  

The intended White-move filter is simple:

  

```text

Amateur popularity >= current threshold

→ include

  

Amateur popularity < current threshold

→ drop

```

  

No Masters evidence is required.

  

No Elite evidence is required.

  

No trap/threat override exists.

  

## Data kept for an included move

  

Keep the move state needed downstream, including:

  

```text

UCI/LAN move

SAN for display where useful

Amateur probability/popularity

Amateur game statistics as needed

```

  

The exact persisted edge data is owned by [[RM]].

  

Do not retain obsolete Master Threat / Amateur Trap flags in the intended node/move model.

  

## Master Threat

  

`Known:` Master Threat behaviour is discarded.

  

Remove intended behaviour for:

  

```text

Master Threat minimum games

Master Threat smoothing threshold

Master Threat popularity floor

Master Threat continuation depth

Master Threat node/move flags

```

  

Current code may still contain these behaviours until implementation is changed, but they are not future policy.

  

## Amateur Trap

  

`Known:` Amateur Trap behaviour is discarded.

  

Remove intended behaviour for:

  

```text

Amateur Trap minimum games

Amateur Trap smoothing threshold

raw 55% win-rate override

trap flags

trap continuation depth

trap-specific inclusion

```

  

Current code may still contain these behaviours until implementation is changed, but they are not future policy.

  

## White smoothing

  

White smoothing is not required by the intended popularity-only inclusion rule.

  

The old smoothing helper may remain in current code while clean-up is pending.

  

[[M]] keeps White smoothing as deferred legacy policy rather than confirmed intended behaviour.

  

## Inclusion label

  

The current code uses the reason:

  

```text

"Mainline"

```

  

for a move that passes the popularity bar.

  

That label is not needed to make the inclusion decision itself.

  

#question If a human-readable inclusion label is retained in UI/logging, rename `"Mainline"` to wording that describes what was actually established: the move passed the configured Amateur popularity threshold.

  

This naming question does not affect move selection.

  

## Why this matters

  

A3.05 determines which White moves the repertoire covers.

  

The intended policy is now deliberately narrow:

  

> cover sufficiently common Amateur moves

  

This avoids mixing opponent-coverage policy with Masters/Elite evidence used for the separate RESPONSE-selection problem.

  

## Bugs / clean-up

  

#bug Current A3.05 still lets Masters-based Master Threat and Amateur Trap logic alter White-move coverage. Remove those paths from intended implementation.

  

#bug Current downstream trap/threat flags and continuation rules should disappear with the discarded feature.

  

## Result

  

A3.05 should become:

  

```text

candidate White move

→ read Amateur statistics

→ calculate Amateur popularity

→ select move-number threshold from central config

→ popularity >= threshold?

   ├─ yes → include

   └─ no  → drop

```

  

Masters and Elite remain available elsewhere for RESPONSE construction, but not for White OPPONENT coverage.
