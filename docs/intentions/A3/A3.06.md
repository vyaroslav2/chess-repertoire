### A3.06 — Did anything survive?

**What the code does**  
After every White move in the pool has been run through the filter in [[A3.05]], the generator checks whether any moves remain.

In the code, the surviving moves are stored in `whiteCandidates`.

The check is effectively:

`whiteCandidates.length === 0`

So there are two possible paths:

- no moves survived -> go to [[A3.07]];
    
- one or more moves survived -> go to [[A3.08]].
    

At this box, the generator does not make any further judgement about why a move survived. It only checks whether the filtered list is empty or not.

**Why this matters**  
A3 now knows whether there is any White move worth covering from the current position according to the current filter rules.

If at least one move survived, the generator can continue to process those moves.

If nothing survived, that does not automatically mean something has gone wrong. The current chess position might already be game over.

That is why the empty path goes to [[A3.07]] first instead of immediately reporting an error.

**Why it may have been designed this way**  
Likely: the generator needs to distinguish between two very different reasons for finding no White candidates:

- there are correctly no moves because the game has ended;
    
- the game is still live, but the filtering/data path produced no White moves to cover.
    

[[A3.07]] makes that distinction before the generator decides whether the empty result is normal or an error.
