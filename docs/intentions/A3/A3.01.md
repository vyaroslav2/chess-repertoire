### A3.01 — Live position, within budget — from A2

**What the code does**  
A3 begins with the same current position that has just passed the checks in A2.

Nothing is changed at this box.

It is the receiving side of the hand-off from [[A2.16]].

At this point the position has survived the current ordinary depth check and the current trap/threat continuation check.

The algorithm now moves on to deciding which White moves from this position should be covered.

The next operation is [[A3.02]], where the generator gets the human move data for this position. In the code, this is the call to `fetchAllDatabases(node.fen)`.

**Why this matters**  
This box marks the boundary between two different parts of the generator.

A2 decides whether the current position is allowed to continue.

A3 decides which White moves from that position should be included.

A3.1 itself does not fetch data, create database rows or select moves. It simply shows that the position has entered the White-move-selection part of the algorithm.

Because of the depth-limit issue already recorded in [[A2.10]], "within budget" describes the route the current code has allowed through A2. See [[A2.10]] for the related `#bug`.

**Why it may have been designed this way**  
Likely: this box exists mainly to make the entry point into the A3 diagram explicit.

There is no separate A3.01 operation in the code because A2 and A3 are sections of the same continuous generator function.
