### A3.07 — Is the game over here?

**What the code does**  
This box is reached only when [[A3.06]] finds that no White moves survived the filter.

The generator creates a temporary chess position from the current FEN:

`const tempChess = new Chess(node.fen);`

It then asks:

`tempChess.isGameOver()`

If the answer is yes, the algorithm goes to [[A3.10]].

If the answer is no, it goes to [[A3.09]], because a live position with no White candidates is treated as an error.

The chess object is created only from the current FEN. The previous move history is not replayed into it.

Because of that, this check cannot recognise a draw by threefold repetition.[^2][^4]The diagram explicitly records this limitation.

**Why this matters**  
Having no White candidates does not necessarily mean that something went wrong.[^3]

If the game has genuinely ended, there is correctly nothing more for the repertoire generator to cover.

This check separates that normal case from a live position where the generator unexpectedly found no White move to include.

The limitation around threefold repetition means that a position which is game over only because the same position has occurred three times can be treated as still live here.

**Why it may have been designed this way**  
Likely: checking the current FEN is a simple way to distinguish genuine terminal chess positions from unexpected empty White-move results without reconstructing the whole game.

Replaying the full move history would provide enough context to detect threefold repetition as well, but the current code does not do that.
