### A3.09 — No White candidates found — add one to the missing-White-moves count and print an `[ALERT - ERROR]` message. Nothing is left to do here, so the branch just ends -> on to A1.24, then back to A1's loop top

**What the code does**  
This box is reached when [[A3.06]] found no surviving White candidates and [[A3.07]] found that the current chess position is not game over.

The generator:

- prints an `[ALERT - ERROR]` message saying that no White candidates were found after the current move history;
    
- adds `1` to the missing-White-moves counter;
    
- processes no White moves from this position.
    

Because `whiteCandidates` is empty, adding its length to the running White-moves-found total changes that total by `0`.

The later loop over `whiteCandidates` also runs zero times.

The generator then reaches [[A1.24]], prints the normal per-position checkpoint, and afterwards continues with the next position from A1's queue loop.

**Why this matters**  
This box records that the generator reached a position which chess.js considers non-terminal, but A3 ended up with no White move to process.

The current code calls all such cases "Missing White Moves".

That label is broader than the actual situation. It can include:

- genuinely missing move data;
    
- human moves that were found but all rejected by the filter in [[A3.05]].
    

The second case is not necessarily an error. It can be the expected result of the repertoire thresholds: moves existed, but none were common or otherwise eligible enough to include. Listed as a bug in [[A3.07]]. 

So this counter currently mixes "nothing was available" with "nothing qualified".

**Why it may have been designed this way**  
Likely: this was intended as a defensive warning for positions where the generator expected to have something to process but ended up with an empty candidate list.

The alert allows the run to continue rather than stopping the whole generator.

However, the current check does not distinguish missing source data from deliberate filtering, so the warning can also be triggered by normal threshold pruning.
