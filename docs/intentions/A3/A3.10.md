### A3.10 — Nothing to cover, correctly. Nothing is counted and nothing is printed -> on to A1.24, then back to A1's loop top

**What the code does**  
This box is reached when [[A3.06]] found no surviving White candidates and [[A3.07]] confirmed that the current chess position is game over.

The generator does not treat this as an error.

It does not:

- print the `[ALERT - ERROR]` message;
    
- add anything to the missing-White-moves counter;
    
- process any White moves.
    

`whiteCandidates` is empty, so adding its length to the running White-moves-found total changes that total by `0`.

The later loop over `whiteCandidates` also runs zero times.

The generator then reaches [[A1.24]], prints the normal per-position checkpoint, and afterwards returns to the top of A1's queue loop for the next queued position.

**Why this matters**  
This treats "there is correctly no legal continuation because the game is over" differently from "we expected White moves but ended up with none".

A terminal position therefore ends quietly rather than being counted as missing data.

Nothing new is added to the repertoire from this position, but the rest of the generation run continues normally.

**Why it may have been designed this way**  
Likely: a checkmate, stalemate or other recognised terminal position is a normal end of a branch, so it should not appear in the error statistics.

The generator only needs to stop expanding this particular branch and continue with the rest of the queue.
